The JSON format

A manual or FAQ is one JSON object: a few settings and a flat list of pages. Each page holds a list of content blocks. All text is plain text, never HTML.

At a glance

{
  "kind": "manual",
  "title": "Member guide",
  "subtitle": "Signing in, bidding and paying",
  "version": "Version 2.1",
  "updated": "2026-11-05",
  "theme": "classic",
  "numbering": "on",
  "pages": [
    {
      "id": "account",
      "title": "Your account",
      "level": 0,
      "blocks": [
        { "type": "paragraph", "text": "You need an account to bid." }
      ]
    },
    {
      "id": "sign-in",
      "title": "Signing in",
      "level": 1,
      "blocks": [
        { "type": "list", "style": "numbered", "text": "Choose Sign in.\nEnter your email address.\nChoose Continue." },
        { "type": "note", "tone": "warning", "text": "After five wrong passwords your account is locked for 15 minutes." }
      ]
    }
  ]
}

Only title and pages are required. Every other field has a default.

The manual object

FieldTypeDefaultMeaning
title requiredstringShown on the cover (manual) or at the top (FAQ), and in the running header of every sheet.
pages requiredarray of pagesChapters, sections and topics in reading order. It may be empty.
kind"manual" | "faq""manual"Chooses the view. A manual gets the paged view and an FAQ the help-centre view. See Manual or FAQ?
subtitlestring""A line under the title.
versionstring""Free text, such as "Version 2.1". Shown on the cover and in the footer.
updatedstring""The day it was last updated, written YYYY-MM-DD. Shown as "Last updated 5 November 2026".
theme"classic" | "modern" | "friendly""classic"Classic uses serif type and navy. Modern uses sans-serif type and teal. Friendly is rounder and green, with a typeface that is easier to read.
numbering"on" | "off""on"Numbers chapters and sections (1, 1.2, 1.2.1) and figures per chapter (Figure 2.1). When off, figures are numbered through the whole manual.

Pages and levels

A page is a chapter, a section or (in an FAQ) a topic.

FieldTypeMeaning
id requiredstring1 to 40 letters, digits, - or _, unique in the manual. It becomes part of the page's address, so keep it stable once people may have linked to it.
title requiredstringThe page's heading, and its entry in the contents.
level requiredinteger, 0 to 5How deep the page sits: 0 is a chapter (or topic), 1 is a section under the page above it, 2 a sub-section, and so on.
blocks requiredarray of blocksThe page's content, in order. It may be empty.

Why a flat list?

Pages are stored as one list in reading order, and level gives the nesting. A page's sub-pages are the pages after it with a higher level, up to the next page at its own level or above. A flat list is easy to write by hand, validate and diff, and to produce from any language.

pages[ ]levelNumberRead as
001Your account
111.1   Signing in
221.1.1      Two-step sign-in
311.2   Your profile
402Bidding

There are two rules. The first page must be level 0, and a page can sit at most one level below the page before it, so you can't go straight from 0 to 2.

Content blocks

Every block has a type and, for most types, a text. Text is plain: it is escaped, so <b> shows as written, and line breaks are kept. Which other fields a block uses depends on its type. Fields that don't belong to the type are ignored.

paragraph

A paragraph of text. An empty paragraph draws nothing.

{ "type": "paragraph", "text": "Bids are binding.\nThe highest bid wins the lot." }

heading

A sub-heading inside a page. It sits one level below the page's own heading.

{ "type": "heading", "text": "Before you bid" }

list

One item per line. Blank lines are skipped.

textThe items, one per line
style"bullets" (default) or "numbered", for steps
{ "type": "list", "style": "numbered", "text": "Sign in.\nOpen your profile.\nCheck your details." }

note

A highlighted box, labelled "Note" or "Important".

textThe note
tone"info" (default), shown as "Note", or "warning", shown as "Important"
{ "type": "note", "tone": "warning", "text": "We will never ask for your password by email." }

table

One row per line, with cells split by |. The first row is the header. Wide tables scroll sideways on narrow screens.

{ "type": "table", "text": "Method | Fee | Arrives in\nBank transfer | None | 1 working day\nCard | 1.5% | At once" }

picture

A figure with a numbered caption ("Figure 1.2"). In the reader, a click opens it full size.

fileUrlThe image address: https://…, a relative path, or data:image/png|jpeg|gif|webp|svg+xml. Any other address (such as javascript:) is refused, and a "The picture is missing" placeholder shows instead.
altWhat the picture shows, for people who can't see it. Please always fill it in.
captionShown under the picture, after its figure number.
size"full" (default), "medium" (70%) or "small" (45%)
align"center" (default), "left" or "right", for a medium or small picture
fileIdYour own reference to the file, such as a media-library id. The renderer ignores it, so a CMS can store it and fill in fileUrl when it delivers the page.
{ "type": "picture", "fileUrl": "https://example.com/sign-in.png", "alt": "The sign-in form", "caption": "Signing in", "size": "medium", "align": "center" }

Pictures load with the page rather than lazily. A sheet stays hidden until the reader turns to it, and signed storage addresses (S3, Azure) often expire within minutes, so a picture fetched late would fail.

question

A question whose answer opens and closes. It is the main block of an FAQ, but a manual can use it too.

question requiredThe question
textThe answer. Line breaks are kept.
idOptional. A stable address for the answer, unique within the page (1 to 40 letters, digits, - or _). Without it, questions are numbered by their place (q1, q2, …), so a link changes when questions are reordered. Give questions an id once people share links to them.
{ "type": "question", "id": "forgot-password", "question": "I forgot my password. What now?", "text": "Choose Forgot password on the sign-in page." }

Manual or FAQ?

Both kinds use the same format. kind chooses how the document is drawn:

"manual": paged view"faq": help-centre view
Best forDocuments read in order: user guides, handbooks, proceduresLooking up one answer: help centres, support pages
Level 0 pagesChapters, each starting a sheetTopics, on one scrolling page
Cover and page numbersYesNo
SearchHighlights matches, and steps through them page by pageFilters the questions as you type
PrintOne sheet per paperAll questions opened
Usual settingsnumbering: "on", theme: "classic"numbering: "off", theme: "modern"

You can override the choice when rendering: renderManual(json, { view: 'paged' }) or { view: 'faq' }.

Addresses

Every page and answer has an id in the HTML, so you can link to it. The ids start with the id you pass to renderManual() ("manual" by default), which keeps two manuals on one page apart.

WhatAddressExample, with { id: 'help' }
A page or topic#<id>-<page id>#help-account
The cover (paged view)#<id>-cover#help-cover
An answer (FAQ view)#<id>-<page id>-<question id>#help-account-forgot-password

The reader opens the sheet or answer that an address points to, and updates the address as people move around.

Checking and cleaning

renderManual() never fails on bad data. It cleans the data first with normalizeManual():

  • A missing or unknown setting gets its default.
  • A block of an unknown type becomes a paragraph.
  • A level that is out of order is pulled back into order.
  • A page id that is missing or repeated is replaced.
  • A field that doesn't belong to a block's type is dropped.

Use validateManual() where the JSON comes in, so authors hear about mistakes:

import { validateManual } from '@bindpress/manual';

validateManual({ title: 'Guide', pages: [{ id: 'a', title: 'A', level: 1, blocks: [{ type: 'video' }] }] });
// {
//   valid: false,
//   errors: [
//     { path: 'pages[0].level', message: 'the first page must be a chapter (level 0)' },
//     { path: 'pages[0].blocks[0].type', message: 'must be one of "paragraph", "heading", "list", "note", "table", "picture", "question"' }
//   ]
// }

Fields the format doesn't know are allowed and ignored. Data written for a newer version still loads in an older one.

JSON Schema

The format is also a JSON Schema (draft 2020-12), shipped as @bindpress/manual/schema.json. Point your editor at it for autocomplete and checking while you write:

{
  "$schema": "https://chooyee.github.io/bindpress-manual/schema/manual.schema.json",
  "title": "Member guide",
  "pages": []
}

A schema can't express the rules that compare pages with each other: the level order, unique page ids, and unique question ids within a page. validateManual() checks those too.
