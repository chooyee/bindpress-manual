@bindpress/manual

Turn a user manual or FAQ, written as one JSON document, into safe, accessible HTML. Manuals read like a PDF. FAQs work like a help centre.

Try the live demoThe JSON format

What it does

You give it one JSON object: a title, a few settings and a flat list of pages, each holding paragraphs, lists, notes, tables, pictures and questions. It gives you back HTML, drawn in one of two views:

Manual: the paged view

A cover with contents, then one A4-shaped sheet per chapter or section. With the reader script you get a folding contents tree, search with highlighted matches, page numbers, zoom, full screen and print-to-PDF.

FAQ: the help-centre view

Topics on the left, questions that open and close, and a link to every answer. With the reader script, search filters the questions as you type, and you get Expand all and the current topic marked in the list.

Safe by default

Every value is escaped and every picture address is checked, so the HTML can go straight on a page. The reader never uses innerHTML and runs under a strict Content Security Policy.

Works without script

The HTML is complete on its own: a long document for a manual, plain anchors and <details> for an FAQ. The reader only adds to it.

No dependencies, no build

Plain ES modules and one stylesheet. Use them from Node, a bundler or a <script type="module">. Types are included.

npm install @bindpress/manual

Render on a server

This is the usual setup: the server renders the HTML, and the page loads the stylesheet and the reader.

server.js (Express, but any server works) 
import express from 'express';
import { renderManual, validateManual } from '@bindpress/manual';

const app = express();
app.use('/manual', express.static('node_modules/@bindpress/manual/src'));

app.get('/help', async (req, res) => {
  const faq = await loadFaqFromSomewhere();     // your JSON, from a CMS, a file or a database

  const { valid, errors } = validateManual(faq); // optional: catch typos in the data
  if (!valid) req.log?.warn({ errors }, 'The FAQ has mistakes; showing it anyway');

  res.send(`<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="/manual/manual.css">
  <script type="module" src="/js/start-reader.js"></script>
</head>
<body>
  <main>${renderManual(faq, { id: 'help' })}</main>
</body>
</html>`);
});
public/js/start-reader.js 
import { startManualReaders } from '/manual/reader.js';
startManualReaders();

renderManual() escapes everything, so putting its result in your template is safe. You don't need validateManual() for safety. It tells you about mistakes in the data, such as a misspelled block type, that would otherwise be quietly cleaned away.

Render in the browser

With a bundler (Vite, esbuild, webpack and others), import the pieces and insert the HTML:

import { renderManual } from '@bindpress/manual';
import { startManualReaders } from '@bindpress/manual/reader';
import '@bindpress/manual/manual.css';

const manual = await (await fetch('/api/manual')).json();
const target = document.querySelector('#manual');
target.innerHTML = renderManual(manual);   // safe: renderManual escapes every value
startManualReaders(target);

With a script tag

This is the simplest way to use it: one stylesheet, one script, and the manual's JSON in the page. It doesn't use modules or fetch(), so it works on any page, including one opened straight from disk.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@bindpress/manual@0.1/dist/manual.css">

<div id="manual"></div>

<script type="application/json" id="manual-data">
{ "kind": "faq", "title": "Help centre", "pages": [ … ] }
</script>

<script src="https://cdn.jsdelivr.net/npm/@bindpress/manual@0.1/dist/bindpress-manual.min.js"></script>
<script>
  var manual = JSON.parse(document.getElementById('manual-data').textContent);
  var target = document.getElementById('manual');
  target.innerHTML = BindpressManual.renderManual(manual);   // safe: renderManual escapes every value
  BindpressManual.startManualReaders(target);
</script>

window.BindpressManual holds the whole API: renderManual, validateManual, startManualReaders, stopManualReaders and the rest. The JSON can also come from fetch() or your own code.

If the JSON in a <script type="application/json"> block is generated from data people typed, write every < as \u003c (JSON.stringify(data).replace(/</g, '\\u003c')). A </script> inside the text would otherwise end the block early.

As ES modules from a CDN

This is the same without a bundle. Modules are fetched like network requests, so the page must be served over http(s): browsers don't load modules from a page opened from disk.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@bindpress/manual@0.1/src/manual.css">
<div id="manual"></div>
<script type="module">
  import { renderManual } from 'https://cdn.jsdelivr.net/npm/@bindpress/manual@0.1/src/index.js';
  import { startManualReaders } from 'https://cdn.jsdelivr.net/npm/@bindpress/manual@0.1/src/reader.js';

  const manual = await (await fetch('faq.json')).json();
  document.getElementById('manual').innerHTML = renderManual(manual);
  startManualReaders();
</script>

Inside a CMS

Store the manual as one field (a JSON column or a block prop). Then reviewing, versioning, publishing and access rules all cover the whole document at once. A block for a page builder takes one line:

import { renderManual, sampleManual } from '@bindpress/manual';

export const manualBlock = {
  label: 'Manual or FAQ',
  defaultProps: { manual: sampleManual() },
  render: (props, ctx) => renderManual(props.manual, { id: props.id, edit: ctx.edit })
};

With edit: true you get a short summary card for an editor's canvas instead of the whole manual. The data model also has the tree moves an outline editor needs: movePage, addPage, removePage and allowedMoves. See the API.
