API reference

Everything the package exports, the reader, and how to style and secure it.

renderManual(manual, options?)

Renders a manual or FAQ to an HTML string. The data doesn't have to be clean: it goes through normalizeManual() first, and every value is escaped.

import { renderManual } from '@bindpress/manual';

const html = renderManual(json, { id: 'guide' });
OptionTypeDefaultMeaning
idstring"manual"The prefix for every id in the HTML (see Addresses). Use a different one for each manual on a page. Letters, digits, - and _ only; anything else falls back to the default.
view"auto" | "paged" | "faq""auto"With auto, an FAQ gets the FAQ view and a manual the paged view. Set it to pick a view yourself, for example to keep an FAQ in the paged view.
editbooleanfalseWhen true, renders a short summary card (title and first levels) instead, for an editor's canvas.

Returns a string of HTML with one outer element, <div class="x-man …">. It has data-manual in the paged view and data-faq in the FAQ view.

renderBlock(block, options?)

Renders one content block on its own. Pass it a normalized block (see normalizeBlock). The options are headingLevel (the <h…> of a heading block, 3 by default), questionId (gives a question an id and a "Link to this answer" link), and nextFigureLabel (a function returning "Figure 1.2" and so on).

validateManual(manual)

Checks data against the format and reports every mistake, in words an author can act on. Use it where JSON comes in: an import, an API or a build step.

const { valid, errors } = validateManual(json);
// errors: [{ path: 'pages[2].blocks[0].tone', message: 'must be one of "info", "warning"' }, …]

It follows the JSON Schema, and also checks what a schema can't: the first page is level 0, levels go down one step at a time, page ids are unique, and question ids are unique within a page. Unknown fields are allowed.

faqJsonLd(manual)

Returns schema.org FAQPage data for the manual's questions, as JSON text ready for a script element. It returns "" when there are no answered questions. <, > and & are escaped, so no answer can close the element.

const jsonLd = faqJsonLd(faq);
const head = jsonLd ? `<script type="application/ld+json">${jsonLd}</script>` : '';

It is opt-in because search engines expect one FAQPage per page, and only you know whether the FAQ is the page's main content. JSON-LD is data, not script, so a Content Security Policy doesn't need to allow it.

Data model

Pure functions with no DOM. Use them to build an editor or a migration, or to read a manual's structure.

normalizeBlock(raw)The same for one block.
outline(manual)Takes a normalized manual and returns, per page: { page, index, pageNumber, number, chapter, figureStart }. number is "2.1.3", and pageNumber counts the cover as 1.

esc(value) and safeUrl(url, isImage?)

These are the two helpers the renderer uses. esc escapes & < > " ' for HTML text and quoted attributes. safeUrl lets relative and http(s) addresses through. For links it also allows mailto:, and for pictures data:image/…. Anything else is refused: a link gets # and a picture "". It removes spaces and control characters first, so java script: is caught. The result still needs esc() before it goes in an attribute.

The reader

import { startManualReaders } from '@bindpress/manual/reader';

startManualReaders();            // every manual and FAQ in the document
startManualReaders(container);   // only those inside an element, such as after inserting HTML

It starts each manual and FAQ that isn't running yet, and returns how many it started, so it is safe to call again.

Before you remove or replace a manual's HTML (as a single-page app does on leaving a page), call stopManualReaders(container). It removes the readers' listeners on window and document. To run one element yourself, use startPagedReader(element) or startFaqReader(element), which return a function that stops it.

Paged view

  • One sheet at a time, with a folding contents tree. On narrow screens the tree slides over the sheet.
  • Search highlights every match and lists the pages that have matches. Enter goes to the next match and Shift+Enter to the previous one.
  • Page number box, previous and next, zoom from 60% to 160%, full screen, and print or save as PDF.
  • Keys: ← → or Page Up Page Down turn pages, / searches, and Esc leaves full screen. On touch screens a sideways swipe turns the page.
  • A click on a picture opens it full size.
  • The address follows the current sheet, so it can be shared.

FAQ view

  • Search filters as you type. Matching questions open with the match highlighted, and the rest are hidden. A topic whose title matches keeps all its questions. Esc clears the search.
  • Expand all and Collapse all buttons.
  • The topic in view is marked in the topic list.
  • An address that points to an answer opens it. Opening a question by hand puts its address in the address bar, ready to copy.
  • Printing opens every answer. / focuses the search.

Styling

Load @bindpress/manual/manual.css. Everything sits under .x-man, and colours and fonts are CSS custom properties. To restyle, set them on a selector more specific than the theme's:

.my-site .x-man {
  --man-accent: #8a1538;
  --man-body: "Source Serif 4", Georgia, serif;
}
PropertyUsed for
--man-paper, --man-ink, --man-softBackground, text and quieter text
--man-accentHeadings, numbers, links and the cover band
--man-rule, --man-tintLines and borders, and soft backgrounds such as notes, table headers and open answers
--man-body, --man-headText and heading fonts
--man-viewerThe grey "desk" the sheets lie on (paged view)
--man-bar, --man-bar-2, --man-bar-fg, --man-bar-mutedThe reader's toolbar (paged view)
--man-nav-bg, --man-nav-fg, --man-nav-line, --man-nav-accentThe contents tree (paged view)

The outer element also has x-man-theme-<theme> and x-man-kind-<kind> classes, plus x-man-faq in the FAQ view and is-reader once the reader runs. The layout switches to its narrow form when the manual itself is narrower than 760px. That is a container query, so a manual in a sidebar gets it too.

The stylesheet sets no margin around the manual. That is your page's job.

Security

  • Escaping. Every text value goes through esc(), and every picture address through safeUrl() and then esc(). Ids are built only from values that match [A-Za-z0-9_-]. The output is safe to insert into a page.
  • No HTML in the data. The format has no rich text, so there is no HTML to sanitize.
  • Content Security Policy. The HTML has no inline script, event handlers or style attributes. The reader builds elements with DOM methods (never innerHTML), and its only style change is one CSS custom property set through the CSSOM. A policy as strict as default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: works. Add your image host to img-src.
  • Links stay on the page. Every link in the HTML is a # address inside the manual.

To report a vulnerability, see SECURITY.md.

TypeScript

Types are included, generated from the JSDoc in the source. The data shapes are exported as types too:

import { renderManual } from '@bindpress/manual';
import type { Manual, Page, Block, RenderOptions, ValidationResult } from '@bindpress/manual';

Browser support

The renderer runs anywhere modern JavaScript runs: Node 18 or later, Deno, Bun, workers and browsers. The stylesheet and the reader need a browser from 2023 or later (Chrome 105, Safari 16, Firefox 110) for container queries and color-mix(). In older browsers the manual still reads, with the wide layout.
